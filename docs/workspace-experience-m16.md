# M1.6：界面层级与客户侧进度恢复

## 视觉范围

`visual.css` 是在既有样式之后加载的视觉层：深色全局导航、浅色内容区、靛蓝主操作、统一圆角/边框、
中文无衬线字体回退、清晰的成功/待确认状态。没有外部字体或图片服务，也没有更换依赖框架。
助手空态提供三张可填入问题的入口卡片，不会自动发消息。管理员审核页增加静态操作步骤、紧凑数量卡片、
可展开的来源校验信息；步骤说明不冒充实际业务完成状态。商品页只做卡片与主视觉样式统一。

这不是所有页面的逐像素重做，不改变导航权限。系统字体回退因设备而异；Chromium桌面/窄屏检查不等于
真实手机、Safari或完整无障碍认证。截图必须明确是合成API交互场景还是实际服务环境。

## 进度与业务请求

`agentTransport.ts` 单独实现UTF-8流式SSE解码，支持LF/CRLF/CR、注释心跳、多行data和事件ID去重，
单帧大小有界。未以空行结束的尾帧不显示为完整事件，EOF也不代表任务成功。

连接结束或失败后先GET原run的持久化状态；仍执行中时最多进行三次订阅尝试，间隔500/1500ms。
每条流有25秒静默上限（心跳重置），快照GET有20秒上限。自动恢复仅发送GET，不新建run，不重发
confirm/stop/reconcile。预算用尽显示“进度连接已暂停”，用户可手动开始下一次有界读取。
切换会话/组件卸载取消订阅，已结束的订阅不能写入新会话；取消订阅不等于取消服务器任务。

401在JSON解析前处理，因此HTML网关401同样触发既有登录失效流程。HTTP错误正文不作为提示直接展示。
同步互斥锁在React状态更新前阻止单页面重复点击。售后确认/停止请求丢失响应后锁住本次动作，要求先
读取服务器状态；仅UNCERTAIN调用既有明确的“核实提交结果”入口。不会假设停止生成能够撤回已提交的业务。
后端角色、预览、确认授权、幂等和退款规则未改。该锁不是跨标签页锁；跨页面安全仍由Java保证。

包括断流读取/恢复、确认响应丢失、同事件循环重复点击、停止、非JSON401、旧会话迟到响应、
390/1440宽度、原流式Markdown/去重测试，以及既有管理员交互回归。
原Business E2E和Admin review UI工作流仍各自检验真实Java/数据库路径，不能混淆这些证据。
仅上传源码绑定记录、JUnit和选定合成截图，不上传浏览器存储、原始业务日志或模型凭据。

实现依据：MDN Using server-sent events 的UTF-8/多行数据/空行分帧规则；React useEffect 的清理和异步响应竞态规则。
本页描述实现与运行方法；是否验收通过以同一提交的CI及实际产物为准。没有付费生成模型调用、生产数据操作或公网部署。

## M1.6a 修复与证据边界

取消后的迟到HTTP/SSE响应在触发401通知或交付正文之前检查取消状态，不影响新会话登录。
持久化快照事件ID必须严格递增；比当前订阅已接收进度更旧的快照不覆盖界面，也不冒充终态。
补入旧历史事件不能把较新的终态改回运行中。这些是前端有界一致性检查，不是多实例数据库一致性保证。

移动工具栏在窄屏分成标题/人工客服与模型选择两行，避免选择框压在按钮上；增加控件矩形不重叠、
标签不溢出和实际人工客服按钮可点击检查。选定截图在空态滚动起点截取，不把聚焦后的滚动位置当成布局。

首次浏览器失败来自测试初始化脚本在登录跳转后再次写入假凭据。脚本改为同一测试tab仅初始化一次，
原清除凭据断言保留，并新增登录页刷新、再次访问受保护页面后仍未登录的检查；应用登出逻辑未被改写。

锁定安装曾报告依赖高危提示。工作流另保存npm audit细节用于核查（不是通过的安全门禁），不能因为
构建或交互通过就声称依赖无漏洞。只包含公开包元数据，不保存认证配置、业务数据或密钥。
