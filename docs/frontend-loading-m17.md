# 页面按需加载与失败恢复（M1.7）

本次只优化前端 JavaScript 的加载边界，不改变业务接口、身份验证、Java 授权或 Agent 确认规则。

## 页面边界

App 保留登录、身份校验与导航壳；通过模块级 React.lazy 延迟加载购物助手、商城、客服工作台、个人设置、人工咨询、商品管理、导入审核和履约页面。身份校验通过后才渲染受保护页面的 lazy 组件。路径与原有原生链接导航保持一致，没有增加路由依赖或预取全部页面。

accountApi 从个人设置组件中原样拆到独立模块，防止读取昵称时把整个设置页面拉进入口。共享的页面 CSS 仍按原顺序提前加载，保留 visual.css 的覆盖顺序；本次不宣称 CSS 下载体积下降。共享组件仍可能带入其他页面的部分辅助代码，不宣称完全按角色隔离脚本，更不能依赖前端分包保护后端权限。

## 失败恢复

界面资源下载期间显示有语义的加载状态，导航与账户菜单保留可用。模块下载超时（15 秒）、404、错误 MIME 或导入异常显示通用错误，不展示代理响应或内部异常。超时后到达的模块不再挂载。

没有自动重试导入、添加随机查询参数、自动刷新或自动重发业务请求。用户明确点击“重新加载页面”才执行 location.reload，保留当前路径及查询参数；页面提示未保存输入可能丢失，已经提交的操作应到原业务记录核实。渲染异常也由页面边界处理，不能据此判断退款等业务是否成功。初始 HTML/入口脚本自身下载失败不在这个边界可处理的范围内；不支持离线运行。

## 体积与验证

Vite 构建生成 dist/.vite/manifest.json。`scripts/bundle-budget.mjs` 沿 index.html 的 **静态 imports 闭包**对文件去重，分别统计原始字节和逐文件 gzip 字节；动态页面单独列出，不能仅把入口内容搬到提前下载的 vendor 文件来假装变小。

当前门槛：入口静态 JS 不超过 300000 字节、逐文件 gzip 总和不超过 100000 字节、任一 JS 块不超过 350000 字节。四个主要页面必须存在动态入口且不在初始闭包。Workspace experience 使用同一 Node 环境单独构建固定基线 `5ebbf627d6fa62302045b10452e8a87d6c45e774`，要求入口闭包相对减少至少 20%。基线构建只增加 manifest 输出，不修改运行代码。没有提高 Vite 的告警阈值。

```bash
npm --prefix apps/web ci
npm --prefix apps/web run test:unit
npm --prefix apps/web run build
node apps/web/scripts/bundle-budget.mjs --dist apps/web/dist --out .local/bundle/check.json
npm --prefix apps/web run test:delivery
```

输出文件必须不存在，避免覆盖先前证据。最后一个命令需要已经安装项目对应的 Chromium。原 test:workspace 继续验证流式和审核交互；test:delivery 使用 **vite preview 的实际生产分包文件**，但业务接口是明确合成替身。验证无登录不取页面、登录页不取其他功能、助手不取不相关页面、等待时导航可用、404/错误 MIME 的手动恢复，以及超时拒绝迟到模块。

构建体积不是 FCP/LCP、真实网络传输字节或弱网耗时，也不是总代码量减少。压缩按逐文件 gzip 计算，不假设实际服务器启用压缩。真实商城集成仍由原有 E2E 工作流覆盖。现有运行快照不会因拉取源码自动升级，不能覆盖旧数据目录。
